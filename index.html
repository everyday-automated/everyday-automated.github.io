Finished · Data Automation · Interactive Dashboard

Canary Seismic Monitor

Canary Seismic Monitor automatically collects earthquake data from Spain’s Instituto Geográfico Nacional, processes and classifies events by island, stores historical records in CSV, and presents the results through an interactive Dash dashboard.

Architecture: IGN Feed → Scheduled Python Ingestion → CSV History → Watchdog → Dash Dashboard

How it works

  • The application downloads current earthquake events from the official IGN feed.
  • Events are cleaned, deduplicated and assigned to the nearest Canary Island.
  • Historical records are stored in CSV on a persistent Railway volume.
  • Watchdog detects data-file changes and reloads the in-memory dataset.
  • Dash and Plotly present the map, filters, indicators and historical analysis.

Application features

  • Activity map and island filtering
  • Earthquake history, magnitude and depth analysis
  • Safe empty states when an island has no matching events
  • Automatic data updates and persistent history
  • Dockerized Railway deployment with automated tests

What it demonstrates

Real external API/feed integration
Scheduled data automation
CSV-based historical storage
Geographic data processing
Interactive analytical dashboards
Defensive handling of missing data
Automated testing and cloud deployment

Production vs public demo

The Railway application is the live production dashboard and retrieves current IGN data automatically. The public GitHub repository is a portfolio-safe demo that uses a fixed snapshot of real IGN data; it does not expose the private production ingestion system.

Finished · Data Automation · Reporting

Canarias Tourism Pulse

An automated dashboard analysing official Canary Islands tourism data from ISTAC. It turns public or company data into an automatically updated web dashboard and an Excel report published to Google Drive.

Architecture: ISTAC API → Scheduled Python Sync → Validated JSON Snapshot → Dash Dashboard + Excel Report → Google Drive

Features

  • Responsive Dash dashboard with seven thematic tabs
  • Airport passengers, ferries, cruise traffic and tourists by island
  • Accommodation occupancy and availability
  • Tourism spending, KPI and automatic charts
  • Current Excel report generated directly from the web app
  • Background ISTAC data refresh with last-known-good fallback

Architecture

One lightweight service: Python, Dash, Plotly, OpenPyXL, Gunicorn, JSON snapshot, background job, Google Drive and Railway. No database and no separate FastAPI backend.

What it can mean for a business

  • Automate data collection from APIs
  • Replace manually updated Excel files
  • Build an internal or public dashboard
  • Generate Excel reports automatically
  • Monitor data quality and preserve working snapshots
  • Publish the tool as a private or public web app

Active development · Travel Product · Geospatial Platform

Canarias Cerca

Canarias Cerca is a map-first product for exploring the Canary Islands. It combines curated places, transport, events and useful live data in a focused local interface.

Architecture: Vanilla JavaScript + MapLibre → FastAPI → PostgreSQL/PostGIS → Railway

Product scope

  • Beaches, viewpoints, villages, natural pools and local points of interest
  • Transport layers for airports, ports, ferries, buses and tram
  • Events from multiple official sources
  • Live modules reserved for genuinely live information

Data workflow

  • Local content editor for crawling and reviewing official sources
  • Normalization, deduplication and manual approval before publication
  • Geospatial storage with PostGIS
  • GTFS and official transport feeds where available

What it demonstrates

Geospatial product design
FastAPI + PostGIS architecture
Multi-source data integration
Human-in-the-loop content workflow

Product principle

The goal is not to rebuild Google Maps. The interface stays focused on local discovery, orientation and useful island-specific context.

AI Anki Language Assistant

A desktop language-learning app that turns vocabulary, grammar and imported materials into reviewed Anki cards while keeping the user in control before anything is saved.

Workflow: Material / Vocabulary → Candidate Review → LLM Generation → Validation → Queue → Final Review → Anki

Core features

  • Vocabulary and grammar card generation
  • Strict grammar structure validation and self-checks
  • Global duplicate protection across generation, import, queue and Anki save
  • Semantic source-role classification for imported material

Speech & models

  • Local Whisper and cloud STT
  • Piper TTS with multiple languages
  • Multiple LLM providers including free-provider options
  • Human review remains part of the workflow

RAG Language Agent

A conversation and learning agent that retrieves from the learner’s own materials so practice, corrections and suggested expressions stay grounded in what the user is actually studying.

Architecture: Learning Materials → Chunking & Embeddings → Qdrant → Retrieval → LangGraph Conversation → Grounded Feedback

Learning workflow

  • Ingest lesson notes, PDFs and text materials
  • Retrieve relevant fragments during conversation
  • Reuse target vocabulary and structures in context
  • Give feedback tied to retrieved source material

Agent layer

  • FastAPI service
  • LangGraph stateful conversation flow
  • Provider switching for LLM calls
  • Structured outputs for reliable downstream use

Why RAG here

The value is not generic chat. Retrieval keeps the tutor anchored to the learner’s course, notes and chosen material.

AI Content Intelligence Engine

A reusable content-processing engine for turning source URLs, crawled pages or raw text into structured, multilingual drafts while preserving a human approval step.

Workflow: Crawl / Source → Classify → Extract Metadata → Generate ES/EN/PL Drafts → Review / Revise → Structured Export

Pipeline

  • Source URL, text, topic or crawler ingestion
  • Classification and metadata extraction
  • Structured multilingual draft generation
  • Checkpointed review and revision workflow

Human in the loop

The engine prepares content but does not publish automatically. Approval remains a deliberate separate action.

First real use case
